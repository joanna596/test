01 / AI WORKFLOW

從情境到持續迭代

筆記中的 AI 工程流程，核心是先準備可用的脈絡，再讓工具和代理在回饋循環中逐步完成任務。

01 · Knowledge

Session + 知識文件

把當次對話、背景資訊與工作規則整理成可引用的上下文。

KB.md handoff.md PRD.md

02 · Context

Context Engineering

設計提示詞與上下文，讓模型知道目標、限制、資料與下一步。

03 · System

Harness Engineering

用工具、API 或 MCP connector，為模型接上可執行的能力。

04 · Iteration

Loop Engineering

執行、檢查結果、修正，再進入下一輪；逐步提高自主程度。

Agent 的自主程度

筆記把流程型自動化與更自主的代理放在同一條光譜上。可先從明確規則開始，再依任務風險和需求增加代理的決策空間。

預先定義 workflow→自動執行 automatic→自主決策 autonomous

可能的能力介面：API MCP Tools Agent

成本與裝置情境

使用模型時也要考慮 tokenization 帶來的用量與成本；介面則需能適應手機、平板與電腦。

提示：依任務選模型、控制上下文長度，並在目標裝置上檢查顯示。

02 / WEB PRODUCT

把點子做成可用的網頁

先釐清需求和最小可行版本，再選擇簡單的前端路徑；產品成熟後再擴充服務與資料能力。

從需求到 MVP

Product idea→Requirements→PRD.md→MVP

先寫清楚使用者、問題、主要流程和必要功能，再做可以被試用的最小版本。筆記也提到 chatbot、task agent、coding agent 等可能的產品型態。

SaaS Software as a Service　 SPA Single-page app　 PWA Progressive Web App

漸進式擴充

從靜態頁面與單頁互動開始，經過使用回饋再增加功能。

  • HTML / CSS / JavaScript：呈現內容與互動。
  • SVG：適合可縮放的圖形；可依需求輸出 PNG 或 JPEG。
  • 前端：使用者看到並操作的部分。
  • 後端：資料、帳號、商業邏輯與服務介面。

做中學：先做出來，再改善

Learning by doing以可操作的原型取得回饋，將「增強」放在持續迭代裡。

先完成一個可展示的核心流程，再依使用者觀察調整內容、互動和技術選擇。初期可保持範圍精簡，避免還沒驗證需求就過早堆疊功能。

03 / LEARNING DESIGN

把學習活動設計成一個循環

筆記以 EMI 課程為例，從內容輸入、練習到形成性評量，組合不同媒介和語言技能。

內容 → 練習 → 回饋

輸入導向 · Input-oriented

Listening 聽Reading 讀PodcastAudio overview

以 podcast、音訊摘要或閱讀材料提供內容，建立理解基礎。

輸出導向 · Output-oriented

Speaking 說Writing 寫Flashcards 字卡Quiz 小測驗

用口說、寫作與測驗促進提取、表達和自我檢查。

教材與活動→形成性評量 formative assessment→自我檢視與調整

課程中的教師與學生角色，也可隨著活動設計由講授逐步轉向引導與自主練習。

04 / SELF-DIRECTED LEARNING

自主學習，並善用 AI 輔助

SDL（Self-Directed Learning）把學習目標與行動交還給學習者；AI 可以協助準備材料、整理知識與提供練習。

設定方向

決定要學什麼、為什麼學，以及如何判斷自己已經學會。

選擇方法

交替使用聽、讀、說、寫、字卡與小測驗，讓輸入和輸出互相補足。

回顧與修正

觀察評量和練習結果，找出缺口，調整下一輪內容與難度。

手寫筆記也能成為入口

筆記最後延伸出一條數位整理流程：拍攝或匯入手寫內容，透過 OCR 擷取文字，再生成摘要與可搜尋的知識材料。

可延伸的實作方向

  • 把 PRD.md、KB.md 和 handoff.md 作為專案知識文件。
  • 用單頁網頁呈現學習內容，再加入測驗或字卡互動。
  • 讓 AI 依學習者的回饋調整摘要、練習與複習順序。
